# 06 — TypeScript hygiene: make `npx astro check` pass (P2)

`AGENTS.md` instructs contributors to run `npm run astro check` before every PR, but the
command currently reports **59 errors / 0 warnings** (2026-07-07). This brief groups them
into 6 root causes. Do brief **05 (cleanup)** first — one error lives in a file slated for
deletion (`navigation-demo.astro`).

Run this to get the current list:

```bash
npx astro check 2>&1 | grep "error ts" | sed 's/\x1b\[[0-9;]*m//g'
```

## 6.1 Uppercase `.JPG` imports unresolvable (3 errors)

`src/utils/bookCovers.ts` (auto-generated by `scripts/generate-book-covers.js`) imports
`the-book-of-kubernetes.JPG`, `things-my-grandmother-said.JPG`, `this-and-that.JPG`.
The files exist; Vite resolves them at build time, but TypeScript's `*.jpg` ambient module
declaration is case-sensitive, so `astro check` errors.

**Preferred fix (removes the problem class):** rename the three files to lowercase `.jpg`
and make the generator + downloader normalize extensions:

```bash
cd src/images/bookshelf
for f in *.JPG; do git mv "$f" "${f%.JPG}.jpg"; done
node ../../../scripts/generate-book-covers.js   # regenerates bookCovers.ts
```

Then in `scripts/download-book-covers.js` (and the film/game/TV variants if they share the
pattern), lowercase the extension when writing files, so `.JPG` never reappears. Also
check `src/content/bookshelf/*.md` frontmatter `cover:` values for `.JPG` references and
update them (grep: `grep -rn '\.JPG' src/content src/utils src/data`).

**Fallback fix (if renaming is undesirable):** add to `src/env.d.ts`:

```ts
declare module '*.JPG' {
    const src: import('astro').ImageMetadata;
    export default src;
}
```

## 6.2 `unknown` collection entries in dynamic `getCollection` calls (~30 errors)

`src/pages/[...slug].astro` and `src/utils/backlinks.ts` call
`getCollection(category as any)` inside `.map()` over a runtime list, so the merged entry
type degrades to `unknown`, and every `entry.id` / `entry.data` / `entry.body` access
errors.

**Fix pattern** (apply in both files): define a minimal structural type and cast the
collection result once:

```ts
import type { CollectionEntry } from 'astro:content';
import { CONTENT_CATEGORIES } from '../content.config';

type AnyEntry = CollectionEntry<(typeof CONTENT_CATEGORIES)[number]>;

const allPosts = await Promise.all(
    categories.map(async (category) => (await getCollection(category as any)) as AnyEntry[])
);
```

If `CONTENT_CATEGORIES` is a plain `string[]` (not a const tuple), first tighten it in
`src/content.config.ts`:

```ts
export const CONTENT_CATEGORIES = ['evergreen', 'blog', /* … */] as const;
```

(Keep the existing exported name/usage — `getContentCategories()` in
`src/utils/content.ts` already spreads it into `string[]` for runtime callers.)

Then fix the residual errors in `[...slug].astro` by typing the destructured entry:
`const entry = (Astro.props as { entry: AnyEntry }).entry;` and removing the now-redundant
`(entry as CollectionEntry<any>)` casts.

## 6.3 `slug` / `render` / `hoursPlayed` not on the local `Post` type (~8 errors)

Files: `src/pages/tvshelf/index.astro`, `src/pages/tvshelf/[show]/index.astro`,
`src/pages/tvshelf/[show]/[season].astro`, `src/pages/gameshelf/index.astro`.

The hand-rolled `Post` interface in `src/utils/content.ts` doesn't declare `slug` (posts
use `id`) or `hoursPlayed`, and `Post` has no `render` method (only real
`CollectionEntry`s do).

Fixes:
- Where code accesses `post.data.slug`, check the frontmatter schema in
  `src/content.config.ts`: if a `slug` field exists there, add `slug?: string` to the
  `Post['data']` interface in `src/utils/content.ts`. If it doesn't exist in the schema,
  the access is a latent bug — replace with `post.id`.
- Add `hoursPlayed?: number` to `Post['data']` **and** to the gameshelf schema in
  `src/content.config.ts` if game entries actually use it (grep
  `src/content/gameshelf/*.md` for `hoursPlayed:`); otherwise delete the dead read in
  `gameshelf/index.astro:157`.
- `tvshelf/[show]/index.astro:58` calls `.render()` on a `Post` — switch that route to
  fetch real entries via `getCollection('tvshelf')` (it needs rendering, so it needs the
  real entry type, not the slimmed `Post`), or use `render(entry)` from `astro:content`
  on the original entry.

## 6.4 `key` attribute on plain HTML elements (5 errors)

Files/lines: `bookshelf/index.astro:245`, `filmshelf/index.astro:142`,
`gameshelf/index.astro:141`, `tvshelf/index.astro:141`, `shelf/index.astro:197`.

Astro templates do not support React's `key` prop on DOM elements; `astro check` flags it
and it serializes as a literal `key="…"` attribute in HTML. Delete the `key={...}`
attributes — `.map()` output in Astro needs no keys.

## 6.5 `PageToggleTitle` prop union mismatch (2 errors)

`colophon.astro:53` passes `togglePage="current"` and `colophon-history.astro:64` passes
`"past"`, but `ProgressLayout`/`PageToggleTitle` declare `togglePage?: 'now' | 'then'`.
Look at `src/components/layout/PageToggleTitle.astro`: it maps the prop to link pairs.
Extend the union and the mapping to support the colophon pair:

```ts
type TogglePage = 'now' | 'then' | 'current' | 'past';
```

with `'current'` ↔ `/colophon/` and `'past'` ↔ `/colophon-history/` entries in the same
lookup structure used for now/then. (Check the component body for the exact mapping shape
before editing.)

## 6.6 Custom element method on `Element` (4 errors)

`bookshelf/index.astro` (~lines 814–892) calls `el.clearActiveTag()` on
`document.querySelector('tag-list')` results. Type the lookup instead of leaving it as
`Element`:

```ts
interface TagListElement extends HTMLElement {
    clearActiveTag: () => void;
}
const tagList = document.querySelector<TagListElement>('tag-list');
tagList?.clearActiveTag();
```

(The custom element is defined in `src/components/islands/tag-list-island.js`; do not
convert that file — just type the call sites.)
